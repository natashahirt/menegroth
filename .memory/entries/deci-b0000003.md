# Decision: author .memory/ via the storage layer

**Context.** Driving the tree through `memory.server.create_project` / `record` requires importing `memory.server`, whose module-level init constructs a kglite `KnowledgeGraph()`. On this machine (conda Python 3.13, macOS x86_64) that import **crashes natively** - a SIGFPE (integer divide-by-zero) at `memory/server.py:1284`, nondeterministically also a SIGSEGV. In isolation `kglite.KnowledgeGraph()` is fine (8 CPUs); the crash only occurs after `memory.server`'s heavy imports (numpy / pandas / model2vec / tokenizers), pointing at an FP-exception / thread-init interaction between those extensions and kglite.

**Decision.** Author the research tree by writing `.memory/*.md` files directly through `memory.storage` (pure stdlib + yaml, no kglite), using the exact frontmatter schema `create_project` / `record` emit. `.memory/` is angelo's source of truth; the kglite cache is rebuilt from it, so the result is byte-for-byte what the server would have written.

**Follow-up.** The same crash will hit the in-editor `angelo-memory` server (same interpreter). Needs a real fix before the MCP servers, coordinator, and zettelkasten extraction can run here - e.g. a Python 3.11 venv for the angelo console scripts, a kglite rebuild, or pinning numpy/tokenizers thread/FP env. Tracked as a todo.
