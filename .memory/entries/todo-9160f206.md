# A1 — Finish joists-as-beams  (ACTIVE / ITERATING)

Joists are modeled as `Beam` with `role=:joist` (not a separate type). The **framing hierarchy is built** — pattern generation (`StructuralSizer/src/slabs/types.jl` `AbstractJoistPattern`), auto-population (`StructuralSynthesizer/src/analyze/framing/populate.jl`: `populate_levels!`, `derive_framing_level`, `materialize_level!`), connection idealizations (OWSJ pinned releases in `members/defaults.jl`), and Asap wiring (`analyze/asap/utils.jl`: seat eccentricity, `load_routing`). **What is still stubbed / broken:**
- **Joist sizing errors out.** `JoistRoofDeck` and `MassTimberJoist` `_size_slab!`/span paths raise `error("... not yet implemented")`. Steel joists need the SJI table path (`slabs/codes/steel/joist_roof.jl` — `TODO: Load SJI joist tables`).
- **Asap `k_joist` stiffness may be undefined** (documented in `scripts/runners/run_phase7_asap_smoke.jl`) — resolve the joist element stiffness kernel so the FE model is well-posed.
- **Default `prepare!` uses empty `framing_opts`** → no joists unless the caller opts in; decide the default policy.

**Depends on:** Phase E5 (SJI canon must be in corpus before real joist tables/checks). Until then smoke tests inject mock `TimberJoistResult`/`JoistDeckResult`.

**Done when:** a steel joist + metal-deck floor sizes end-to-end with a real SJI selection, the Asap model solves with defined joist stiffness, and load routing (`:cell_tributary` / `:shell_area`) is validated against a hand tributary calc.
