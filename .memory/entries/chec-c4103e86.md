## What

speed.md lever #20: when `_rc_section_check` checks an installed column section that is a **catalog** section, and the sizing stage (`_fit`/`_grow`/`_stack`) already built the full-catalog P-M capacity cache for that `(checker, catalog, material, objective)`, the check now **indexes into that cache at the section's catalog index** instead of building a one-section diagram cache. A refinement of #10/#19.

## Structure (`flat_plate_column_check.jl`)

- Factored the memo key + validity rule out of `_memo_capacity_cache` into `_capacity_cache_key` and `_capacity_entry_valid` (identity guards on catalog/material/objective + `cache_matches`) so builder and reader share one validity rule. The identity guards matter: `cache_matches` does NOT compare εcu or the objective coefficients, so `material === material` (pins εcu) and `objective === objective` are what keep a reused diagram exact.
- `_peek_capacity_cache(checker, catalog, material, objective)` — GET-only memo lookup; returns a validated full-catalog cache or `nothing`. Never builds (so we never integrate a whole catalog just to check one section).
- `_catalog_section_index(opts, section)` — identity `IdDict{section=>j}`, memoized per catalog (`_CATALOG_INDEX_MEMO`), O(1). `set_section!` stores the catalog object as-is, so `section(col) === catalog[j]` by identity.
- `_column_capacity_slot(checker, opts, section, material) -> (cache, index)` — peek-hit for a catalog section returns `(full_catalog_cache, j)`; else falls back to `(_memo_section_cache(...), 1)`. `_rc_section_check` now asks for a slot and runs is_feasible/explain_feasibility at that index.
- Env gate `SS_DISABLE_COL_CATALOG_SLOT` forces the fallback (for the equivalence harness).

## Exactness

`is_feasible`/`explain_feasibility` read `depths[j]`, `diagrams[j]`, `diagrams_y[j]`, and the cache material props. `catalog[j] === section` (identity) + peek's `material === material` + `cache_matches` make all of these bit-identical to the one-section cache. Joint path (`jchecker`, joint material) isn't in the memo, so it peek-misses and falls back cleanly — no regression, no gain there yet.

## Magnitude (calibrated)

Modest, bounded refinement — removes the single-section P-M integrations in the column-check path. Those were already memoized by section identity, so the saving is ~(distinct catalog sections ever installed) × one diagram integration, bounded by catalog size and cheap vs the full-catalog build that already happened. Value is as much cleanup (one unified capacity-cache abstraction) as raw seconds.
