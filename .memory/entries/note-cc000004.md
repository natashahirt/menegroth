# What: the HTTP API and the (existing) agent layer

Served by **Oxygen**. Bootstrap `scripts/api/sizer_bootstrap.jl` binds host/port immediately (default 0.0.0.0:8080), serves `/health`+`/status` while it async-loads the package and calls `register_routes!()`. `SERVER_STATUS` is a single-runner, latest-wins queue; `/design` returns **202 + poll** (async, to dodge App Runner's 120s timeout) with results in `DESIGN_CACHE`.

Core endpoints: `/health`, `/status`, `/schema` (+ `/schema/applicability`, `/schema/diagnose`, `/schema/tools`, `/schema/llm_contract`), `/validate`, `/design`, `/result`, `/logs`, `/diagnose`, `/report` (text or `?format=json`), `/rebuild_visualization`, `/reset`, `/env-check`.

JSON boundary: wire structs via StructTypes+JSON3 (`api/schema.jl`), `json_to_skeleton`/`json_to_params` deserialize into Unitful, `design_to_json` serializes with display-unit conversion, SHA-256 geometry hash (params excluded) for cache reuse.

**An LLM agent surface already exists** (relevant to goal a): `POST /chat` (SSE, OpenAI-compatible, `CHAT_LLM_*` env) with a system prompt injecting geometry context + tool specs + history; `POST /chat/action` for direct tool dispatch. `api/tool_registry.jl` holds `TOOL_REGISTRY` (~30 tools in 3 phases — orientation / diagnosis / exploration, e.g. `get_situation_card`, `get_diagnose`, `query_elements`, `run_design`, `compare_designs`, `predict_geometry_effect`, `run_experiment`, `narrate_element`) plus `IMPLEMENTED_PROVISIONS`. This is a natural consumer of the angelo knowledge graph once it is live.
