Addressed the issues surfaced in the skeptical review.

## #1 Orthogonality guard (safety gap fixed)
`reentrant_critical_section` builds a strictly 90° d/2×d/2 notch, but `classify_corner_kind` tagged ANY slab angle >π as :reentrant — so a skewed (e.g. 135°) inside corner would silently get the wrong geometry (non-conservative).
- Now store `Column.corner_angle` (slab-material angle, radians) + 2-arg `classify_corner_kind(angle, position)`.
- `check_punching_for_column` routes to the general engine ONLY when `corner_kind==:reentrant && corner_angle ≈ 3π/2` (atol 0.12). Skewed re-entrant (angle ≠ 3π/2) and cols lacking `corner_angle` fall through to the conservative 2-sided corner check (over-predicts — safe). Angled-notch geometry is a future feature.
- Tests: skewed (225°) and bare stubs fall back to 2-sided b0; orthogonal (3π/2) routes. 58/58 Sizer, 13/13 Synth.

## #2 resolved by #1
The latent risk was 'untested path hits wrong geometry.' The guard removes that — any corner that routes is provably orthogonal; everything else is conservative. Remaining 'not exercised by current rectangular generators' is benign.

## #3 Demand-side audit (KEY FINDING: primary path is correct)
`Vu = qu × Atrib`. `compute_column_tributaries!` computes Voronoi tributary **per incident cell** and SUMS over all cells touching the vertex (`col_totals[key] += area`). So a re-entrant corner, incident to ~3 cells, automatically accumulates ~3× a convex corner's tributary — same incident-face mechanism as `slab_material_angle`. **Primary demand path correctly handles re-entrant; no bug.**
- The ONLY unsafe spot was the no-cache FALLBACK in `_compute_column_shear`: `:corner → A_base/4` (one-quadrant) would understate a re-entrant Vu ~3×. Fixed to be corner_kind-aware: `:reentrant → 3·A_base/4` (three quadrants, conservative). Only fires when the Voronoi cache is absent (degenerate); production always has the cache.
- Unbalanced-moment (Mub) side: DDM is not applicable to irregular/L plans anyway (§13.6.1.1) — such buildings fall back to FEA, which extracts real moments. Vu (dominant punching term) is the one that matters and is correct.

## Minors
- αs=40 concern resolved by the guard (only true 4-sided orthogonal re-entrant routes).
- Rotated columns (θ≠0) and re-entrant-not-cached: consistent with the EXISTING corner check (c1/c2 treated as moment-aligned for all positions; re-entrant polygon is cheap). No new risk; left as-is.
