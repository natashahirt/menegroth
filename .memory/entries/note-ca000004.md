# Cross-ref: how the stack uses Asap

**StructuralSizer** does `@reexport using Asap` for the whole unit surface, converts sized sections to FEM sections via `to_asap_section(section, material) -> Asap.Section` (`StructuralSizer/src/members/sections/to_asap_section.jl`), reuses polygonal-section tools (`CompoundSection`, `sutherland_hodgman`, `depth_from_area`) for PixelFrame flexure, and builds mixed `Asap.Model` + `ShellTri3` for the flat-plate FEA pipeline.

**StructuralSynthesizer** gets units indirectly via `@reexport using StructuralSizer`, `import Asap` for FEM types, and bridges building geometry to FEM through **`to_asap!(struc; ...)`** (`StructuralSynthesizer/src/analyze/asap/utils.jl`), which builds nodes, frame elements, `TributaryLoad`s, and optional `Shell`/`Diaphragm` diaphragms. `BuildingStructure.asap_model::Asap.Model` holds the live FEM; the design workflow calls `Asap.process!`/`Asap.solve!` repeatedly during sizing iterations. `_ensure_asap_units!()` re-registers units in `__init__`.

**Expected authoring path:** units first (`using Asap`/reexport), build model (`Node` -> `Element`/`Shell()` -> `Model`), `process!` then `solve!`, extract nodal `displacement`/`reaction` (Unitful after solve) and `ElementInternalForces`/`ShellInternalForces`. At building scale, prefer `to_asap!` + `to_asap_section` over hand-building sections.
