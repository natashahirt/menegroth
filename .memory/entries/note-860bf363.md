Current behavior (left as-is on purpose). `standard_rc_columns` (`StructuralSizer/src/members/sections/concrete/catalogs/rc_columns.jl`) builds each candidate with clear cover. `RCColumnSection` throws `ArgumentError` from `_check_column_bar_spacing` when adjacent longitudinal bars are closer than ACI 318-19 §25.2.3 (corpus: aci-318-19, p. 469): clear spacing at least the greatest of 1.5 in, 1.5 d_b, and (4/3) d_agg. The catalog catches that and skips the section, so it never enters the discrete catalog. The MIP therefore cannot pick it. When the steel only fit by crowding the bars, the solver has to take a larger bar or a larger column. Same answer as rejecting the section in the checker, and a smaller catalog. `explain_feasibility` cannot name the missing section, because it was never a candidate. The user deferred that visibility.

How to add it later, without changing which section wins:

1. The constructor currently refuses to build an illegal layout, so the catalog cannot keep the section unless the check moves. Add a keyword on `RCColumnSection` (default on) that skips `_check_column_bar_spacing`, and build catalog sections with the check off. Leave the default on for every other caller (NLP builder, `design_column_reinforcement`, reconciliation), so hand-built and solver-built sections still cannot exist in violation.
2. In `ACIColumnChecker._is_feasible_rc_column` (`StructuralSizer/src/members/codes/aci/columns/checker.jl`), reject a section whose bars fail §25.2.3. Use a non-throwing form of `_check_column_bar_spacing` (`rc_rect_column_section.jl`) so the checker returns false instead of throwing.
3. `explain_feasibility` on the same checker mirrors `_is_feasible_rc_column` and collects the ratios. Add a record there with the clause, the actual minimum clear spacing, and the required spacing, so a diagnosis can say the section was rejected for bar spacing rather than simply not appearing.
4. The MIP still cannot select those sections, so the chosen member stays the same. They re-enter the catalog, so the catalog is larger again and the MIP speedup from dropping them goes away. That is the tradeoff.

Tie size is the same shape. `_check_tie_bar_size` enforces ACI 318-19 §25.7.2.2 (p. 501) in the constructor. Surface it the same way if a diagnosis should name an undersized tie.

The NLP path is separate and already visible at build time. `_rc_column_nlp_fit_bars` caps placeable steel at the count that fits at the current b × h, and `build_rc_column_nlp_result` throws when nothing builds. Do not route that through `explain_feasibility`.
