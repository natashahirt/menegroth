## Question
Why did steel_rib_composite on topology/r2c1 run 10.5 h and fail group 8 with Vu=1772 kN / Mu=2100 kN·m (every section fails shell_deflection_ll, closest W36X652 at 1.09), when the frame-only gravity solve gives only 356 kN?

## Decisive data (diag_slab_thickness.jl, diag_story_shell_composite.jl)
- Slab is a **127 mm two-way topping**, SW 2.96 kPa, factored 9.30 kPa — NORMAL weight, not a heavy slab. Load magnitude is fine (~4.5 MN over 480 m²). So the earlier 'two heavy stacked systems' framing was wrong on the weight.
- Floor carries **116 one-way composite steel joists** AND is declared floor_type=:two_way.
- Side-by-side on IDENTICAL nominal W24X76 sections (topology/r2c1, level 1):
  - FRAME (one-way joist tributary, diaphragms=:none): worst joist V=356 kN, M=1479 kN·m.
  - STORY-SHELL (two-way plate meshed + every joist hung below as an offset/composite frame): worst joist **Vu=1189 kN** (×3.3), Mu=664 kN·m (×0.45). Eight beams all >870 kN.

## Mechanism
The story shell meshes the 127 mm slab as a **two-way plate** and hangs all 116 joists below it as frames offset to the slab mid-plane (T-beam / composite action). That turns a one-way joist floor into an over-stiff, highly redundant two-way grid. Load redistributes by stiffness: midspan **moment drops** (continuity) while support **shear spikes** — the signature seen (M down, V up). Heavier/stiffer composite sections concentrate MORE, so the sizer chases a runaway (stiffen → more concentration → stiffen …): nominal W24X76 → 1189 kN, real composite W36X652 → 1772 kN. That runaway is both the 10.5 h non-settling story_shell_passes loop AND the final shell_deflection_ll infeasibility.

## Root cause (config contradiction, not a shell/tributary bug)
_steel_rib_composite in scripts/runners/sdf_nova_topology_systems.jl pairs composite steel joists (SteelBeamOptions(composite=true)) with params.floor = TwoWayOptions(). Composite STEEL ribs offset under a two-way plate is not a real system. Contrast the systems that work: concrete_rib (waffle) = two-way slab + MONOLITHIC concrete ribs (genuine two-way → shell correct); steel_deck = ONE-WAY composite metal deck (no two-way plate). The two-way declaration is what the shell faithfully models; the composite-steel stiffening on top of it is the problem.

## Fix direction (not yet applied)
steel_rib_composite should use a one-way composite deck/slab (like steel_deck), NOT TwoWayOptions. If a two-way slab is genuinely intended, the steel ribs must not be modeled as a composite two-way grid. Earlier tributary 'leak' (find-d1ef9cef 1.41x / 13% diagonal) was disproven — tributary conserves area exactly (find-60964611); the only real cause is this story-shell two-way concentration.
