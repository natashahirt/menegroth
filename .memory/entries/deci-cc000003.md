# Why: separation of structure and design

- **`BuildingStructure`** = geometry + loads + tributaries + mutable sizing state; reusable across many parameter sets.
- **`BuildingDesign`** = the results of ONE `DesignParameters` set (multiple designs per structure).
- `design_building` **restores `struc` after each run** via `snapshot!(:prepare)` + `restore!` (`core/snapshot.jl`), so parametric sweeps don't accumulate mutations.

Related conventions:
- **Two Asap models on purpose**: `struc.asap_model` = design-phase frame model; `design.asap_model` = richer viz/analysis shell model built post-capture by `build_analysis_model!`.
- **Architectural vs structural centerlines**: `geometry_is_centerline` + `structural_offset` on edge/corner columns, captured before restore.
- **SI storage, display at the boundary**: all `BuildingDesign` results in m/m²/kN/kg; `DisplayUnits` (imperial/metric) applied only at serialize/report.
- **Geometry hash excludes params and `stories_z`** so param sweeps reuse the `BuildingStructure` and story-Z rebuilds don't cause spurious cache misses (`api/cache.jl`).
