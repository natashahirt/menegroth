# How: solver trace + feasibility explanation

- `TraceCollector` / `TraceEvent` (`trace/trace.jl`): an optional `tc` kwarg threaded through the pipeline; `emit!` is a no-op when `tc === nothing`, so tracing is zero-cost when off.
- `@traced` macro: a compile-time contract that populates the global `TRACE_REGISTRY` (`Dict{Tuple{Symbol,Symbol}, TracedFunctionMeta}`); `scripts/runners/audit_trace_coverage.jl` verifies coverage. Where docstrings/`@traced` conflict, entries are registered manually (`slabs/sizing.jl`, `members/optimize/api.jl`, `discrete_mip.jl`, foundations).
- Trace layers: `:pipeline`, `:workflow`, `:sizing`, `:optimizer`, `:checker`, `:slab`.
- `explain_feasibility` (per-checker overrides + default in `optimize/core/interface.jl`) returns a `FeasibilityExplanation` with per-check `ratio` and `code_clause`; `optimize_discrete` calls it post-solve for assigned sections. The `companion=:explain_feasibility` annotation documents that `is_feasible` pairs with it.

This machinery is what surfaces "why did this member fail / govern?" to StructuralSynthesizer's `get_solver_trace` agent tool and diagnose JSON.
