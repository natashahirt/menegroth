# Decision — out-of-plane / slender wall (ACI 318-19 §11.8)

Coordinator run `run-oop11p8` (rigor=high). Canon: `note-w0000014`
(corpus: sp-de-tilt-up-wall-aci19).

## What was decided

1. **Adopt the §11.8 Alternative Method for Out-of-Plane Slender Wall Analysis**
   as the out-of-plane capability, implemented in a new
   `StructuralSizer/src/walls/out_of_plane.jl` (sibling of the in-plane
   `flexure.jl`), rather than the general §6.6 moment-magnifier or a full FE
   column-analogy. Rationale: §11.8 is the code-sanctioned closed method for
   tilt-up / precast slender bearing-wall panels, has a fully-worked
   spWall-validated oracle in the corpus, and its applicability envelope is
   explicit and checkable.

2. **Treat applicability as a hard safety boundary, not advisory.** The checker
   evaluates gates §11.8.1.1(b) tension-controlled, (c) φMn≥Mcr, (d) Pu≤0.06f'cAg,
   (e) Δs≤lc/150, plus P-Δ magnifier stability (Pum<0.75·Kb). Any gate failure
   returns a FAILED `CheckResult` citing the specific governing clause — the
   method is inapplicable outside its envelope, and a silent pass there would be
   dangerously unconservative.

3. **Per-design-strip API.** All section properties (`As`, `Ig`, `Ag`) are per
   tributary strip of width `b`, distinct from the in-plane pier `WallSection`
   geometry. The core is bare-SI and WallSection-free; a Unitful wrapper resolves
   materials with the same `fy`/`Es` Unitful-pressure guard as `flexure.jl`.

4. **Second-order coupling is intrinsic.** Unlike the demand-decoupled shear /
   in-plane P–M checks, `Mu` here is the P-Δ-magnified moment
   `Mua/(1−Pum/(0.75·Kb))`, so the checker consumes factored loads directly.

## Validation

Standalone oracle smoke test `scripts/smoke_wall_oop.jl` reproduces the spWall
tilt-up worked example — **16/16 checks pass** (run in isolation, immune to
concurrent package edits): Ase 7.764 vs 7.76 in², c 0.8955 vs 0.896 in,
Icr 354.9 vs 353.56 in⁴, Kb 98.02 vs 97.64 kip, Mua 24.77, Mu 60.65 vs 61.00
kip-ft, Mcr 46.32, φMn 96.06 vs 95.89 kip-ft, Δu 9.90 vs 9.995 in, Δcr 0.550,
Δs 0.2475 vs 0.247 in, σ_axial 38.66 vs 240 psi limit; all gates applicable.

## Integration + review/critic hardening — 2026-07-14 (commits b41fff4b, 740fe774)

Integration completed (foreign lease cleared): wired (`_walls.jl` include +
`StructuralSizer.jl` exports), `test_walls.jl` known-answer + gate suite, report
§3P. **Walls suite 122/122; report 7/7 stages pass.**

Independent **blind reviewer** (verdict PASS) traced all 11 oracle numbers to the
source (`.../reference/Tilt-Up Wall ACI 19.txt`) and confirmed no fabricated
clause. Adversarial **critic** (verdict CONCERN) found two P1 **fail-open
serviceability** paths, both fixed in `740fe774`:

1. `svc.converged` was discarded — a non-converged bilinear/P-Δ service iteration
   could return a too-small `Δs` that spuriously passes `Δs ≤ lc/150`. Now the
   check FAILS (clause `11.8.4.1`) if the service iteration does not converge.
2. Gate (e) was silently skipped when service loads were omitted — a strength
   "pass" without the mandatory §11.8.1.1(e) limit. Now the check `@warn`s and the
   `CheckResult.name` flags gate (e) as unverified (never a silent full pass).

Minor (reviewer): the shared `_wall_flexure_materials` error text was mislabeled
`check_wall_inplane_flexure` when reached via the out-of-plane path → made
function-agnostic. The CheckResult now exercises gate (e) end-to-end with the
documented service loads (Pa=7.20 k roof DL, ws ⇒ Msa=20.32 kip-ft ⇒ Δs=0.247 ≤
2.36 in).
