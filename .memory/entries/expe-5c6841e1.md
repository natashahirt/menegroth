CHANGE (StructuralSizer/src/optimize/solvers/discrete/model.jl): in the separable case (n_max_sections==0), the solution extraction now canonicalizes each group's pick to the LOWEST catalog index among feasible sections that achieve the same minimum objective coefficient as the solver's pick. Two mirror groups with identical demands + identical feasible set + an equal-cost tie would then resolve to the SAME section. Tests: StructuralSizer concrete_beam/test_tbeam_optimization.jl + optimize/test_multi_material_mip.jl 130/130 PASS.

RESULT (full e0c0 waffle, ~15min): STILL chiral -- NE=SW=T18x36-bf42, NW=SE=T20x30-bf20.

INTERPRETATION: the fix is a no-op for e0c0 because the split is NOT an equal-objective-coefficient MIP tie. T18x36-bf42 and T20x30-bf20 have DIFFERENT objective coeffs, so each diagonal's separable MIP deterministically picks its own cheapest section FOR ITS OWN DEMAND. Since the MIP is deterministic and covariant, two mirror diagonals only get different sections if their DEMANDS already differ when they reach the MIP.

KEY correction to the bistability reasoning: global cost is trivially equal under a mirror swap (sum over members is swap-invariant) -- that does NOT imply the two sections have equal per-member coeff, and they don't. So the bistability is in the DEMAND-FEEDBACK loop, not a cost tie.

NARROWED SEED HYPOTHESIS: with symmetric sections the FEA is bit-exact mirror (proven), so equal sections -> equal demands. For the demands to diverge while sections are still symmetric, the PER-GROUP REPRESENTATIVE DEMAND computation (member_group_demands: sample the signed-moment field at `resolution` stations along each chain and reduce to a max) must be reflection-ODD -- most likely because the two mirror chains are PARAMETERIZED in opposite directions (_ordered_chain_vertices orientation is vertex-index-based = x-odd), so the discrete sampling grid hits different physical points on the two mirror beams and the sampled max differs by a hair, enough to tip the MIP onto different sections at some pass. NEXT: audit member_group_demands sampling/reduction for orientation dependence; make the sampled representative demand reflection-invariant (symmetric station set or continuous max).

BOTH fixes so far (check_settle reflection-invariant _pick_group_section + mix-first settle; optimize_discrete canonical tie-break) are correct, cost-neutral, principled improvements to reflection-covariance and are kept -- but neither is the e0c0 carrier.
