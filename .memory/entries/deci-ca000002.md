# Why/how: Asap's unit convention

`external/Asap/src/Units/units.jl`. Constructors accept any compatible `Unitful.Quantity` (dimension aliases `Length`, `Force`, `Pressure`, ...), but **internal FEM state is stripped to SI Float64**: positions in m, forces in N, pressures in Pa, rotations in rad, stored bare in `K`, `S`, `u`. Boundary converters (`to_kip`, `to_ksi`, `to_inches`, `to_meters`) do the crossing.

Custom US-customary units (`kip`, `ksi`, `psf`, `pcf`) are registered via `Unitful.register(Asap)`; `__init__` re-merges `_localunits`/`_localpromotion` snapshots so registration survives precompilation (a recurring Unitful+precompile gotcha, hence the defensive `_ensure_asap_units!` downstream).

**`kgCO2e` is defined on a distinct Unitful dimension `𝐗`** so embodied carbon can never silently add to structural mass (`kg`). Material *presets* deliberately do NOT live in Asap — StructuralSizer owns catalogs and converts via `to_asap_section`. This keeps Asap a pure FEM+units core.
