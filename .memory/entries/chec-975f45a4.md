**Workstream R.1 (continuous-section abstraction) — first overnight slice.**

New pure-numeric module `src/optimize/section_relaxation.jl`, placed next to `drift_optimality.jl` (loads before `members/sections/`, so it works on `Float64` I/A/Z tables in SI, not section objects — matching the existing "vectors in/out" contract).

API:
- `SectionScalingLaw` + `fit_section_scaling_law(I, A; Z)` — log–log least-squares power-law fit over a catalog family (A ≈ exp(a)·I^b, same for Z), sorted ascending in I.
- `continuous_area(law, I)` / `continuous_modulus(law, I)` — smooth continuous price of a stiffness target.
- `marginal_area(law, I) = b·A/I = dA/dI` — the weight-per-stiffness coefficient `w_e` that `drift_optimality_resize` already consumes. This is the concrete link R.1→drift resizer.
- `project_to_catalog(law, I_target)` — lightest catalog entry with I ≥ target (argmin A, robust to non-monotone A); `nothing` ⇒ grow catalog.
- `candidate_band(law, idx, k)` — clamped ±k warm-start window for the discrete MIP.
- `projection_gap(law, I, idx)` — per-member area optimality gap.

These are EMPIRICAL CURVE FITS to catalog geometry, not code-derived provisions — no safety factor/capacity equation here; discrete owners still certify strength/stability. Documented as such.
