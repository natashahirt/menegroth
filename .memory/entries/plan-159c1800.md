User decisions (2026-11-08): objective is lexicographic (thinnest slab that passes, then the smallest columns at that thickness); before thickening, try shear studs at the failing column; look up ACI 318-11 §13.5.3.3 and bring it back for sign-off before any code; prototype on the 3x3 individual FEA plate and compare analysis count and final sizes with today's loop, coordinating with the iteration session (plan-b10cde0c step 5, faster punching) before merging.

Why it ratchets today: `_resolve_punching_failures!` (:grow_columns) walks each failing column to the cap, one analysis and FEA remesh per step, and bumps h only at the cap. A corner column draws more unbalanced moment as it stiffens, so the walk reaches 30 in. Phase A restarts with columns still at the cap. Nothing shrinks: v5 ended with 20.5 in floors, 21 in columns, punching ~0.54.

Algorithm:
1. Phase A minimum h (deflection, one-way shear, flexure) as now (`_jumped_depth`).
2. Probe a thickness: reset columns to their axial and P-M minimum, analyze once, size each column (or studs) against frozen demand with the existing fixed-demand resolver, confirm with one analysis; repeat only while columns still grow at that h.
3. A column failing at the cap with studs marks h infeasible; predict the next h from that column at the cap, with no analysis in between.
4. Bracket and bisect h on the half-inch grid; ~2 analyses per probe.
5. Trim: try one step thinner with fresh columns.
No code check changes. Every accepted design is confirmed by an analysis.

§13.5.3.3 (aci-318-11, page 250): not implemented (`gamma_f` is Eq. 13-1 only). Interpretation questions are with the user. If adopted, punching (γv = 1 − γf) and final-design transfer reinforcement (§13.5.3.2, `_pipeline_transfer_reinforcement`) must use the same γf.
