User agreed the trust-tier idea is good.

Tiers (highest to lowest):
1. Canon: a building-code provision, corpus-cited (source_id + clause + page).
2. Verified behavior: 'our code implements this equation', backed by a test.
3. Empirical: 'our code behaves like this', backed by experiments, pinned to a code version.
4. Hypothesis: heuristic or LLM prior, awaiting test.

Rules: knowledge moves up a tier only with evidence; every answer carries its tier; tiers are never blended, so empirical knowledge about menegroth is never presented as a code provision (consistent with the ENGINEERING JUDGMENT labeling rule in corpus.mdc). Knowledge in any tier never alters checks, factors, or pass/fail outcomes.

Implication: nearly all of the current hand-written ontology.jl (PROVISION_ONTOLOGY misconceptions, SYSTEM_DEPENDENCIES economic ranges, CODE_RATIONALE) sits at the hypothesis tier; its mechanism text can be re-anchored to canon citations.
