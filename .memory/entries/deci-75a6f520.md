## Problem
Every `test_quiet.jl` run spawned a fresh Julia process. Measured on macOS with uncommitted edits: cache rebuild 312 s (StructuralSizer) / 931 s (StructuralSynthesizer); warm load 25 s / 37 s. Any StructuralSizer edit also invalidates StructuralSynthesizer.

## Decision
- New `scripts/runners/test_server.jl <Pkg>`: activates the package env, stacks the root env (only place Revise lives; overlapping deps OrderedCollections/Requires are the same versions so no rebuild), loads Revise then the package, listens on 127.0.0.1 (port written to `logs/test_server_<Pkg>.port`). Each request runs `Revise.revise(throw=true)` then includes the files in a fresh anonymous module under one top-level `@testset`, output (incl. C-level solver output) redirected to the client's log.
- If Revise cannot apply an edit, the request returns code 2 and NO tests run (never test stale code).
- `test_quiet.jl` auto-uses the server when reachable, falls back to a fresh process on missing/stale port file; `--fresh` forces a clean process.

## Verified
Server run 7-9 s first time, 0.3-0.5 s repeat (vs 30.6 s fresh). Revise picked up an added + modified probe function; syntax error refused then recovered after fix; stale-port fallback works.

## Caveats
Package-level mutable state persists across runs -> use `--fresh` for final verification. Restarting still precompiles if stale. Agent sandbox may block localhost connect (client falls back). Shells ignore SIGINT for background jobs; Ctrl-C works in a real terminal.
