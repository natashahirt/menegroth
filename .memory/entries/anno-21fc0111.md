Observed while landing Run 6 warm-state (commit f9070e1a) and reading the peer joist work in StructuralSynthesizer/src/analyze/asap/utils.jl.

Gap: the joist load-path fix wires `_create_framed_slab_loads!(loads, ...)` into `to_asap!` (initial assembly, around lines 189-206 of the peer-diffed file), routing framed-slab pressure onto the joist elements. But there is NO companion helper wired into `sync_asap!` — the sync path re-calls `_sync_shell_area_pressures!` and `_sync_vault_thrust_line_loads!` but does not re-emit the joist TributaryLoads. So on a `load_combinations` (or self-weight) change:
  - Calling `sync_asap!(struc; params=new_params, loads_only=false)` will call `Asap.update!` which rebuilds P from the *current* model.loads — which still contain the STALE joist tributaries from the last `to_asap!`. Total applied gravity force will not match the new envelope pressure; the girder demand will be wrong.
  - Calling `sync_asap!(struc; params=new_params, loads_only=true)` (Run 6 Part A, commit f9070e1a) additionally REUSES the cached CHOLMOD factor — same stale-load bug, plus the reused factor is valid only under 'K unchanged, loads changed'. The pre-condition holds (K unchanged) but the LOAD CHANGE never actually reaches the model. Result: bit-identical to the stale-load full sync, i.e. wrong-but-consistent.

Repro sketch (not exercised in Run 6's verify because gen_medium_office is a flat plate with no joist framing): (1) build a 2-way framed bay with `populate_levels!` joists; (2) `to_asap!(...)` → joist tributaries applied; (3) `sync_asap!(...; params=with_new_combos)` → shell + thrust-line pressures update but joist tributaries do NOT; (4) solved girder V/M reflect old combo, not new.

Fix direction (peer-session, not Run 6's problem): add a `_sync_framed_slab_loads!(struc, params)` helper mirroring the load emission in `_create_framed_slab_loads!` and call it from `sync_asap!` before the `Asap.update!` dispatch. It must clear the prior joist TributaryLoads (or replace them by identity) so the new envelope pressure is emitted exactly once, with no double count. The `_slab_has_joist_framing` gate keeps unframed slabs on the byte-identical existing path.

Cross-thread relevance:
- Run 6's default (`loads_only=false`) path is safe on unframed / flat-plate buildings and consistent-with-stale on framed buildings; Run 6's opt-in `loads_only=true` path is safe on unframed and consistent-with-stale on framed. Neither is 'wrong' by Run 6's own contract (K unchanged); both are wrong-in-consequence for framed buildings because loads didn't actually change. So this gap needs to close BEFORE any framed-building warm-state or incremental-engine work.
- The Run 6 verify harness `scripts/runners/verify_warm_state_incremental.jl` should grow a framed-building fixture once this closes, to exercise the joist-tributary sync path under the same warm==cold bit-identity gate.
