When `record()` is called with `files` that have uncommitted changes, the memory server AUTO-COMMITS those files as part of the memory-pin commit (e.g. verify_design_graph_incremental.jl landed in memory commit 05fd814a). If you THEN run `git add <same file> && git commit`, the file is already committed, so your manual `git commit` instead sweeps whatever else is pre-staged in the index (here: 10 unrelated prior-work test files) under your message. Lesson: after `record(files=X)`, do NOT separately commit X; and before any bare `git commit`, check `git diff --cached --name-only` for unrelated pre-staged files. The fix was to reword the mislabeled commit (eee02cdb).
