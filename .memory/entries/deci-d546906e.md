Follow-up to the max_iterations=12 fix. Goal: stop a convergence shortfall from masquerading as a strength failure, and (attempt) faster settling.

PROBLEM PRECISELY. When _iterate_beams_columns! exhausts max_iterations without a strict section fixed point, _record_member_convergence! sets stage_diagnostics[:members]; capture_results.jl:847 then forces EVERY sized beam ok=false (it will not trust per-member checks off a fixed point), and summary.jl:150 floors the fail ratio to 1.0 (r_fail = r<1.0 ? 1.0 : r). So a slow-but-valid design reads as 'Beam 1144 flexure 1.0' overstress. The conservative all-fail stance is deliberate and safe; only its *surfacing* as a fake 1.0 is the defect.

PART A - GRACEFUL DEGRADATION (implemented). New _verify_installed_design!(struc, params, beam_opts, column_opts) in StructuralSynthesizer/src/workflow/check_settle.jl: re-solves and runs _beam_group_report + _column_group_report on the sections ALREADY installed, returning true only when every beam group and every column group passes its sizer's own checker on the final analysis; on success it records those checks onto the members. It is strictly weaker than a fixed point (does not require a resize to re-pick the same sections) so it cannot pass an unsafe design. Wired into _size_beams_columns! right before _record_member_convergence!: if !converged, converged = _verify_installed_design!(...). Guarded by _settle_checkable (same guard _check_settle! uses); returns false (keeps the design not-settled) for unverifiable option sets. Rib deflection stays a separate slab check, so accepting here cannot hide a deflection failure.

VALIDATION (grid/x1y1 dense_waffle, scripts/runners/sdf_dense_waffle_converge_diag.jl with SDF_DIAG_MAX_ITERS override + verify logging): at a forced cap the verify DOES run on ribs - it checked all 1444 beam groups + 9 column groups (so _beam_group_report's check_tbeam_section verifies rib-owner-chosen T-sections fine; NOT a no-op for ribs). cap=4 and cap=8 both correctly REFUSED: at cap=8, 5 of 1444 beam groups still fail their final-analysis check (0/9 columns). So the ~9-12 passes are genuinely needed sizing work, not wasted hunting - at pass 8, 5 rib groups are still under-designed vs the final analysis; they only resolve near the fixed point. Carbon was already 225.2 kgCO2e/m^2 at cap=8, i.e. the design is ~99.7% settled by then. Tests: lints clean; 510/510 (test_check_settle + test_rib_grillage + test_solid_head_check + test_solid_head_story) pass.

PART B - SPEED (not done; found not safely available). The existing upward-only/section_floor ratchet is EXCLUDED for T-beams: size_beams_story_shell.jl:184 throws unless _shell_ratchet_ok (rectangular concrete or steel only), and the code states 'T-beams are not floored'. A true per-pass speedup would need a NEW monotonic ratchet inside the rib owner - a deep, carbon-sensitive change. More fundamentally, because 5/1444 groups are genuinely still failing at pass 8, cutting to 3-4 passes would ship under-designed ribs; speed conflicts with adequacy here.

NET: keep max_iterations=12 (genuinely needed to settle the last groups) + Part A as the graceful/correct safety net so a cap-hit that nonetheless verifies reports pass with a 'reached cap' note instead of a fabricated 1.0, and a genuine non-convergence refuses safely. For THIS waffle Part A does not trigger (it reaches a strict held fixed point by ~pass 9-12); its value is robustness for other jobs/geometries that land verifiable-but-not-strict-fixed-point.
