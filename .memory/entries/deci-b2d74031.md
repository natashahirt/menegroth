## Decision
Scoped floor overrides (ScopedFloorOverride, per-zone floor-system selection) MUST inherit params.column_I_factor for their column stubs — route the override's effective floor options through _apply_col_I_factor(.., params.column_I_factor) so overridden cells use the same column cracking factor as the rest of the building.

## Rationale (user)
col_I_factor is a **column-type property** (cracked Ig for column stubs per ACI 318-11 §10.10.4.1), ORTHOGONAL to the floor system in a zone. A scoped override selects a floor SYSTEM (vault / flat-plate / flat-slab + method/deflection/punching) for a region — it is not a column-stiffness selector (the struct has no col_I_factor field). Columns are shared/global structure; you might zone columns independently (e.g. steel columns here, concrete there) regardless of slab type. A single analysis model with mixed 0.50/0.70 column stubs depending on which floor zone sits above is an internal inconsistency, not an intentional per-zone design.

## Context
Before Change 1, ALL cells used 0.70 (consistent). Change 1 moved non-overridden cells to params.column_I_factor but left overridden cells at the 0.70 default (_scoped_override_floor_opts utils.jl:265 builds FlatPlateOptions without col_I_factor; _process_single_slab_group utils.jl:672 discards the resolve_floor_options result for overridden cells). So Change 1 itself introduced the split — inheriting restores consistency.

## Rejected alternatives
- 'Own' (self-contained zone stiffness): not actually a user knob today — ScopedFloorOverride has no col_I_factor field, so it would just hardwire 0.70 for overridden zones. Exposing a real per-zone column knob would need new API surface (col_I_factor on ScopedFloorOverride + deserializer) — a separate feature, not this fix.
- Defer: leaves a known 0.50/0.70 inconsistency in the model.

## Implementation (folded into Change 1 fix cycle)
Apply _apply_col_I_factor to effective_floor_opts in _process_single_slab_group (StructuralSynthesizer/src/analyze/slabs/utils.jl), threading the resolved column_I_factor into that scope. Byte-exact no-op at default 0.70.
