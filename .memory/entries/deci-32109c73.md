## Problem
`SS_ENABLE_HEAVY_PRECOMPILE_WORKLOAD` defaulted to true in code while docs/Dockerfile/API/~40 runners set it false. ENV is not part of Julia's precompile cache key, so whichever process triggered a rebuild decided the cache contents; test_quiet.jl didn't set it, so routine test runs paid the heavy workload (2x design_building + steel MIP): StructuralSynthesizer cold load 931 s.

## Decision
- StructuralSynthesizer reads `heavy_precompile_workload` (default **false**, matching docs) via `Base.record_compiletime_preference` + `Base.get_preferences` (what Preferences.@load_preference does; avoids adding a dep). Preferences are in the cache key, so toggling rebuilds correctly.
- `scripts/runners/dev_precompile.jl off|on|heavy|status` writes gitignored LocalPreferences.toml in root/Sizer/Synth/Studies envs (`off` = PrecompileTools `precompile_workload=false` for both packages).
- Removed the dead ENV from Dockerfile and docs workflow; docs updated. Runner scripts still set the old var (harmless no-op), as does untracked scripts/runners/cluster/env.sh.

## Verified
Cold `using StructuralSynthesizer` (rebuilding Sizer+Synth): 330 s vs 931 s; `ENABLE_HEAVY_PRECOMPILE_WORKLOAD=false`, Gurobi still detected. dev_precompile off/on round-trip writes then removes files; files are gitignored.

Shared files with user WIP (StructuralSynthesizer.jl, .gitignore) committed hunk-only in a follow-up commit.
