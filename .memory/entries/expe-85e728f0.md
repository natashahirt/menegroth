## Context (Slice 3 of the continuous-optimization workstream)
Slices 1-2 replaced genuine coupled ratchets (drift across walls; self-weight axial across columns in an indeterminate frame) with single certified MILPs. Slice 3 was proposed as a joint slab-thickness × column MILP for flat plates. Recon showed a production `punching_strategy = :joint_search` already exists (chec-ac48f14e): one analysis scaled to each half-inch thickness, and at each thickness every column takes its cheapest passing size/stud option by embodied carbon.

## Why a MILP is redundant here (unlike Slices 1-2)
At a FIXED slab thickness every column's punching is LOCAL — demand (Vu, Mub) from its own strip, capacity from its own section and the depth. The columns are INDEPENDENT; there is no cross-member coupling and no ratchet. So the problem is: pick one thickness from ~tens of candidates → each column independently takes its cheapest passing option. That separates completely, so the pruned scan already returns the global grid optimum. A MILP would need the full capacity matrix (no short-circuit) plus solver overhead for the SAME answer. The only genuinely coupled case is cross-slab SHARED columns (two-level floors), which is gated on ACI 318-11 §13.5.3.3 sign-off and deferred.

## What shipped (no new mechanics; production byte-identical when the flag is off)
- Refactored `joint_search` to build its scan from shared closures `_joint_scan_closures` (thickness list, scaled-demand `at`, `depth`, `slab_term`, `concrete_term` lower bound, `preference`) + `_joint_column_terms(cl, ctx, full)`. Behavior-preserving.
- Added the exhaustive reference `brute_force_joint_optimum` (and `_joint_column_option_full` / `_full_size_grid`) that disables BOTH prunings: every thickness scanned (`lower_bound=-Inf`, no concrete early-stop) and every column size on the increment grid evaluated (no cheapest-passing short-circuit). Reuses the identical `check_punching_for_column`, `_try_reinforcement`, and cost terms, so any disagreement would be a pruning defect, not a mechanics difference.
- Gated self-check in `joint_search` (`SS_PROVE_JOINT_SEARCH=1`) logs production's minimum feasible objective vs the exhaustive minimum into `JOINT_PROVE_LOG`. Compares MIN feasible J (not best.J), so the test is pure optimality, independent of the 1% tie rule / preference.
- Runner `scripts/runners/joint_search_proving_slice.jl`: 3×3 30 ft-bay DDM flat plate, 12 in start columns; four configs (studs, no studs, studs priced out via stud_weight=1e6, MinVolume).

## Result
All four joint_search calls: production minimum feasible objective == exhaustive grid minimum to **rel.err 0.00e+00**, same chosen thickness (11.99 in), 11 feasible thicknesses in the pruned set. The early-stop and the per-column short-circuit provably skip nothing cheaper.
