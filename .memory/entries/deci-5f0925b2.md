# Implementation-readiness review — complete wall system plan (plan-a2a6128f)

Reviewed the plan against the actual codebase and folded two adjustments into `.cursor/plans/complete-wall-system_76ac3f3b.plan.md`.

## Verified green (de-risks the plan)
- The performance foundation already exists: `Asap.solve(model, cases)` does a non-mutating multi-RHS solve reusing the cached factorization (`StructuralSynthesizer/src/analyze/asap/utils.jl`, `_solve_with_patterns!`, ~line 854), and `sync_asap!(loads_only=true)` preserves the CHOLMOD factor bit-identically (lines 550–640). Lateral load cases are a new consumer of existing paths — not greenfield.
- Asap already solves mixed frame+shell models (`fem_evaluator.jl`), so wall shells in the building model are within the existing library; no `external/Asap` edits implied.
- Incremental Design Graph, snapshot/restore, and the warm-vs-cold exact-first gate (`plan-1004cfac`, `scripts/runners/verify_warm_state_incremental.jl`) are in place.

## Top risks (ordered)
1. Unified-model refactor can regress the validated gravity path: wall skeleton edges are currently `:fixedfixed` frame placeholders in `to_asap!`; converting to shells risks stiffness/self-weight double-counting and touches rigid-diaphragm linking, load routing, and drift semantics. Highest-regression step.
2. Chicken-and-egg: phase 4 (performance) cannot benchmark the phase-5 unified model before it exists.
3. Seismic mass couples back into gravity design (weight → base shear → sizing → weight) — a second convergence loop beyond wall-force redistribution.
4. Loads-only bit-identity holds only for pure-RHS cases; P-Δ and accidental torsion perturb effective stiffness and must be explicit separately-fingerprinted solves.
5. §18.10 canon is OCR-degraded with no extractions — a true hard gate before phase 9.

## Two adjustments folded into the plan file
(a) Phase 4 rescoped to deliver performance CONTRACTS + BASELINE BENCHMARKS + CACHE STUBS only; actual cache/warm-state implementation lands with the unified model in phase 5 behind the same exact-first gates. Added an explicit pointer to the existing `Asap.solve(model, cases)` / `sync_asap!(loads_only=true)` primitives.
(b) Added an end-to-end VERTICAL-SLICE milestone after phase 7 (one solid ordinary wall, one simple building, one wind + one seismic direction, through the unified model to serialized results + report, with cold-vs-warm and gravity-non-regression gates passing) as a blocking gate before phases 8–11. Also promoted phase 5's validation into two NAMED MANDATORY GATES: unified-vs-isolated `FEMLateralEvaluator` equivalence, and gravity bit-identical non-regression when no lateral design is requested. Added a `vertical-slice` todo and tightened the P-Δ/accidental-torsion wording.

## Concrete unknowns to resolve per gated phase

- `Wall.story` (0-based ground) vs `StoryLoad.story` (1-based) indexing contract in `to_wall_line` when generators emit `:walls` edges.
- Whether rigid-diaphragm master/slave linking stays SPD once wall shell nodes join the story constraint set.
