Keep the Ipopt RC column path (`sizing_strategy = :nlp`) and fix its gap between the smooth surrogate and the built section. Do not rewrite it as an exact solver. The default RC column path is already the discrete catalog, which checks every candidate with ACIColumnChecker. An exact rewrite would duplicate that path. For speed, the better lever is plan item 3 (binary-search routing on the catalog).

Two fixes:
1. As-built verification: every returned NLP column section, whatever the Ipopt status, is checked with the real ACIColumnChecker at its actual bars and dimensions. A failing section is stepped up (more bars, then larger dimensions), or the status becomes :infeasible. This replaces the ρ_opt-based :converged gate.
2. Placeable steel: a smooth NLP constraint ρ·b·h ≤ n_max·A_bar using the same 32-bar cap as `_build_nlp_trial_section`. Ipopt then cannot ask for steel that the bar cap will remove.

Shape: one engineer (Grok 4.7 high), then a Sol critic (GPT 5.6 Sol medium), one fix cycle.
