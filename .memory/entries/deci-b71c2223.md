During Run 3 (fine per-group nodes), the eng-groups engineer surfaced a load-bearing contradiction and stopped rather than guess (correct per code-accuracy.mdc).

BLOCKER: The invalidation tests as originally specified require 'change ONE slab's / one beam group's params -> only that group's node recomputes, siblings skipped.' But EVERY slab/member knob in DesignParameters is GLOBAL (floor, materials, beams, columns, loads, scoped_floor_overrides). Fine per-group nodes are roots off the fixed prepared baseline, so their input_hash = f(node_key, param_slice, base_hash). Any global param change flips the param-slice hash for ALL sibling fine-nodes simultaneously -> they all recompute. Within-building INDEPENDENT per-group variation is therefore STRUCTURALLY IMPOSSIBLE without new per-group parameter addressing. (scoped_floor_overrides is prepare-affecting — changes grouping + per-cell floor_type — so it cannot serve as the per-slab handle; Run 2 classified it correctly.)

OPTION A (deferred, NEEDS USER SIGN-OFF): add NON-prepare-affecting per-group override params, e.g. slab_sizing_overrides::Dict{Int,…} (per slab_idx) and member_group_overrides::Dict{UInt64,…} (per group id), carrying only sizing-time knobs that size_slab!/size_member_group!/sync_asap! honor over the fixed baseline (explicitly NOT floor_type/grouping/loads). Each fine node hashes only its own entry, so changing slab 3's override dirties only slab-3's node. This is the ONLY way to get within-building per-group reuse, but it is NEW mechanics + a safety-critical prepare-affecting classification (same class of decision as Run-2's pattern_loading vs load_combinations) — a product/API + safety call the human owner must make. Not to be invented autonomously overnight.

DECISION (coordinator, for the overnight run): proceed with OPTION B — exact-first, no new mechanics. Build the fine per-slab-idx + per-beam-group node topology, partial snapshot/restore, and multi-node-per-level scheduler correctness (all provably equivalent to design_building), plus the thrust-governed vault fixture. Reframe test assertions to the ACHIEVABLE exact-first claims: (1) fine decomposition is output-equivalent to coarse size_slabs!/from-scratch; (2) CROSS-STAGE reuse over fine nodes still holds (:beams-only -> only beam nodes; :foundation_options -> only foundations; column-catalog -> coarse column node, not slabs); (3) multi-node-level: global slab change dirties all slab nodes, they all recompute, level barrier syncs once, output-equivalent. Option B's infra (topology + partial snapshot + multi-node level) is the exact foundation Option A builds on — not wasted.

WHY B ADDS NO WITHIN-BUILDING REUSE TODAY (be honest): under global params, slabs are already upstream, so a column/foundation change never dirtied the coarse slab node either — fine slab nodes provide reuse ONLY once Option A (within-building per-group variation) or content-addressed cross-building keys (Phase 4/5 batch dedup, the 'identical member reuse' the user described) exist. Option B is foundational plumbing + exact-first proof; the payoff is unlocked by A and/or Phase 4/5.

FOR THE USER, when back: approve Option A (per-group override params) for a follow-up run? Confirm which sizing-time knobs are safe to expose per-group as non-prepare-affecting (the exact-first gate will prove equivalence, but the API/knob choice is yours).
