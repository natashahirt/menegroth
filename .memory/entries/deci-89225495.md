## P0-1 — wire incremental design engine into the API/chat loop

PARAM-ONLY design changes now reuse a cached `DesignSession` via `redesign_incremental!` instead of a cold `design_building`, gated by an exact-first cold-vs-incremental equivalence test. Safety-critical structural API; exact-first contract.

### Design
- **Shared helper** `_design_with_incremental!` (routes.jl) used by BOTH cold call sites: `_execute_design` (routes.jl ~L648) and `run_design` (chat.jl ~L4543).
- **Cache extension** (cache.jl): added `session::Union{DesignSession,Nothing}` + `session_base_params` fields; `clear_session!`; session cleared on geometry change via `reset_session_state!`.
- **Kill switch** `_api_incremental_enabled` reads `SS_API_INCREMENTAL` (default ON).
- **Param-only predicate** `_param_only_change`: `isempty(intersect(Set(changed_param_fields(base_params(session), new_params)), Set(StructuralSynthesizer.PREPARE_AFFECTING_FIELDS)))`.
- **Routing**: param-only + live session => `redesign_incremental!` with try/catch fallback to cold; prepare-affecting / no-session / kill-switch-off => cold `design_building` + eager `DesignSession` construction (wrapped). A predicate throw now falls back to cold rather than HTTP 500.
- **Lock model**: heavy `redesign_incremental!` / `design_building` moved OUT of the `DESIGN_CACHE.lock` critical section (lock now only guards session-read+predicate and result/session store) so GET /status is not blocked. Race-safe because `SERVER_STATUS` (RUNNING) serializes designs across the helper at both sites — the incremental engine is NOT concurrency-safe.

### Equivalence gate
`test/design_graph/test_api_incremental_equivalence.jl`: 9/9 exact-first checks PASS — cold `design_building` == incremental `redesign_incremental!` byte-for-byte on per-member `design_signature` (rtol=1e-8) across flat-plate + beam/column fixtures (variations: load_combinations, foundation-soil, optimize_for, member_group_overrides), PLUS an adversarial capped-`max_iterations` case (flat-plate cold@1 != cold@20, a real stress) confirming `max_iterations` is correctly param-only. ~11.5 min on HiGHS (no Gurobi).
