Goal: every sizing loop finishes or says why it did not, the analysis model is rebuilt only when something it depends on changed, and a fresh design and an incremental redesign agree by construction. Builds on note-00712354 (audit) and plan-bff9aa9f (measured hot spots). Does not change any code-derived equation; steps that would (punching prediction) need corpus clauses and sign-off first.

## Why
- Fixed-point loops are hand-written in five places with different stop rules: flat plate (`size_flat_plate!`: outer, Phase A depth, Phase B punching, all sharing `max_iterations`), beams/columns (`_iterate_beams_columns!`, 5% column-demand change), story shell (`_size_with_story_shell!`, 3 rounds), P-delta (`p_delta_iterate!`), wall thickness (`_maybe_confirm_wall_thickness!` recursing into `design_ordinary_walls!`, cap 2 or 6).
- A count cap cannot tell 'still improving' from 'stuck'. The 3x3 FEA flat-plate fixture in test_design_graph_incremental.jl stops at FLOOR_DESIGN_NOT_CONVERGED (punching) and the log cannot say which.
- Three ways to refresh analysis: `to_asap!` (full rebuild, also called by `apply_wall_thickness!`), `sync_asap!` (loads_only or full), `_reanalyze_after_section_change!`. Callers pick; nothing records why.
- Two-level slab nodes run the full floor design in propose AND in commit (`_push_two_level_slab_nodes!`).
- Incremental redesign differs from fresh at `col36.interaction_ratio` on the 3-story DDM fixture: some input is read but not declared.

## Architecture
1. One iteration contract. A sizing step is analyze -> check -> propose -> apply. Proposals only grow on a discrete grid (catalog, whole inches) up to a limit, so the loop terminates without a count. A small shared driver returns the final state plus a status: converged / stalled (nothing grew, a check fails; names it) / at_limit / budget (backstop only). Status is separate from installability (existing contract: a non-converged floor is never installed). Migrate one loop at a time; wall jump already follows this shape (`_thickness_grows`), flat plate is the second caller, then beams/columns and story shell.
2. Predict, then confirm. A step may use one analysis to predict the smallest passing size with demand frozen, then confirm with one re-solve, as the wall jump does. Confirm is mandatory when the change moves relative stiffness. Per-check sensitivities need corpus grounding (punching: ACI 318-11 §11.11) and are not written until scoped.
3. One analysis owner with typed changes. Stages report what they changed (loads, sections/stiffness, geometry/thickness/mesh); one `update_analysis!` picks the least work: re-solve with the existing factorization, refactor in place, or remesh. Finite-element work stays in Asap (architecture-contracts.mdc). Counters record each kind per stage.
4. Coupling is explicit, not recursive. Stages return proposals; the driver decides to re-run. Wall jump stops calling `design_ordinary_walls!` from inside itself. Cross-stage feedback (slab columns <-> frame columns <-> walls <-> foundations) is a declared outer loop with the same status contract.
5. Declared reads/writes are the cache key. Every node's inputs (including live column sizes and moments) are part of its fingerprint, so incremental == fresh by construction. Per-entity snapshots replace whole-structure deepcopy memos (audit P0-2).
6. Measure. Counts of analyses, factorizations, remeshes per stage go into the trace; tests assert budgets (e.g. `:all` wall jump <= 3 analyses). Small fixtures for loop logic; building-scale runs stay as integration tests.

## Order
1. Status outcomes in `size_flat_plate!`; separate budgets for outer, Phase A, Phase B; run the 3x3 fixture to see stalled vs still growing.
2. Find the undeclared input behind `col36.interaction_ratio`; make column state a declared slab-node input.
3. Commit reuses the proposal when the envelope did not change that slab's supports.
4. Counters per stage; baseline the four building fixtures.
5. Shared monotone driver; move wall jump and flat plate onto it; remove the wall-stage recursion.
6. `update_analysis!` with typed changes; route `apply_wall_thickness!`, `_reanalyze_after_section_change!`, and sync through it.
7. Punching predict-and-confirm after corpus review and sign-off.

Steps 1-6 are control flow, caching, and bookkeeping only.
