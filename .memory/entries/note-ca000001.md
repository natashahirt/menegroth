# What: Asap module layout & core types

Single top-level `module Asap` (`external/Asap/src/Asap.jl`) that `include`s submodules; the only nested Julia module is `AsapSections` (arbitrary polygonal sections, re-exported at top level).

Areas: `Units/` (unit system), `Materials/` (Material, ShellMaterial, Ply/Laminate CLT), `Sections/` (Section, TrussSection; + `AsapSections/` polygon centroid/inertia + Sutherland-Hodgman depth analysis), `Nodes/` (6-DOF `Node`, 3-DOF `TrussNode`), `Elements/` (frame `Element{R}`, `BridgeElement`, `TrussElement`; `shell/` T3FF `ShellTri3`/`CompositeShellTri3`; `spring.jl`), `Loads/` (NodeForce/LineLoad/GravityLoad, `TributaryLoad`, `AreaLoad`), `Tributary/` (straight-skeleton edge tributaries, Voronoi vertex tributaries, spans), `Model/` (`Model`/`FrameModel`/`ShellModel`/`TrussModel`, assembly/solve), `Dynamics/` (mass, modal), `Nonlinear/` (buckling, P-Δ, pushover), `Analysis/` (internal forces, displacements, shell queries).

Element end-releases are **type parameters** (`Element{FixedFree}` etc.), so release handling is dispatched, not branched. `Model` is the unified mixed frame+shell type; interior shell-mesh nodes are merged by object identity.
