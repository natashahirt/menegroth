User-approved resolutions for the two items deferred from the main I_factor threading (deci-8299ff3e).

## Change 1 — Flat-plate `col_I_factor` SSoT: DO BOTH (FEA sync + EFM edit)
Make `params.column_I_factor` the single source of truth for flat-plate columns across **all** analysis methods:
- **FEA**: inject `@set opts.col_I_factor = params.column_I_factor` in `resolve_floor_options(params)` (StructuralSynthesizer/src/design_types.jl ~757). FEA path (`.../flat_plate/analysis/fea/model.jl`) already consumes `opts.col_I_factor` via `_col_asap_sec(...; I_factor=col_I_factor)`.
- **EFM**: StructuralSizer/src/slabs/codes/concrete/flat_plate/analysis/efm.jl currently **ignores** the incoming `col_I_factor` kwarg and derives it: `col_I_factor = (solver==:asap && cracked_columns) ? 0.70 : 1.0` (3 sites ~225, ~470, ~1881). Edit: on the cracked branch use the **incoming** `col_I_factor` instead of the literal `0.70` (uncracked stays `1.0`), preserving the `cracked_columns` gating. Plumbing already exists (pipeline.jl passes `col_I_factor = opts.col_I_factor` at ~1171/1434). **Byte-exact no-op at default** (incoming default 0.70 → cracked gives 0.70). Cite ACI 318-11 §10.10.4.1 (0.70 = default cracked value). **This edits StructuralSizer**, which the main threading round deliberately avoided — now explicitly in scope.
- **DDM**: `col_I_factor` unused (API parity) — no change.

## Change 2 — PixelFrame / FRC: HOLD
`to_asap_section(::PixelFrameSection; I_factor=0.70)` already applies the factor but is never fed the knob. Decision: **do NOT** thread the generic RC `beam_I_factor`/`column_I_factor` into FRC/PixelFrame. Rationale: ACI 318-11 §10.10.4.1 governs conventional RC only; PixelFrame is FRC + external post-tensioning (fib Model Code territory), and its existing 0.70 ('prestressed → less cracking') is already a judgment value. Applying an RC cracking knob to FRC has no fib Model Code basis. Keep PixelFrame on its own 0.70; revisit with the corpus (fib MC) if FRC cracked-stiffness control is needed later.
