# What: StructuralSizer layout (~237 files)

Entry `StructuralSizer/src/StructuralSizer.jl`. Load order matters and is: `trace/` -> `types.jl` -> `Constants.jl` -> `loads/` -> `materials/` -> `optimize/` -> `codes/` -> `members/` -> `slabs/` -> `foundations/` -> `visualization/`.

Directory responsibilities:
- `trace/` — solver decision trace (`TraceCollector`, `emit!`, `@traced`, `TRACE_REGISTRY`); loaded first so every submodule can annotate.
- `types.jl` — root abstract types (`AbstractMaterial`, `AbstractDesignCode`, `AbstractSection`, `AbstractDemand`, `AbstractMemberGeometry`).
- `loads/` — ASCE 7-22 combinations, occupancy gravity presets, ACI pattern loading.
- `materials/` — steel/concrete/FRC/timber types + presets, ECC distribution registry, fire-protection coatings.
- `optimize/` — SHARED optimization infra (`AbstractCapacityChecker`, `AbstractNLPProblem`, objectives, JuMP solvers); loaded before `members/` so solvers depend only on abstract interfaces.
- `codes/` — SHARED element-agnostic design math (ACI material props, Whitney block, deflection, punching, fire, PCA tables; AISC fire) used by both members and slabs.
- `members/`, `slabs/`, `foundations/` — per-domain sections, code checks, NLP problems, sizing APIs.
- `visualization/` — section-geometry traits only (rendering lives in StructuralSynthesizer).

**`walls/_walls.jl` is an empty placeholder, NOT included** — no wall design code is active.
