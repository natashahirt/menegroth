Audited _share_collinear_rib_bars! / _collinear_rib_groups (collinear_ribs.jl):

1. GROUPING is geometrically unambiguous and symmetric. The hub (12,10) joins two diagonals: NE dir ∝ (6,5) and SW dir ∝ (6,5) are collinear through the shared node -> group {NE,SW}; NW ∝ (6,-5) and SE ∝ (6,-5) -> group {NW,SE}; NE×NW cross = -60 != 0 so the two diagonals never merge. The cross-product test (tol 1e-3) and DFS give the same two groups regardless of traversal order. This is exactly the observed C2 pairing -> collinear sharing is WHY NE=SW and NW=SE, and it is correct/symmetric.
2. SHARING is order-independent: shared bar size = maximum(bar_of[mi]) over the line (line 301); edge bw/h = maximum (lines 308-309). maximum over a set is reflection-symmetric, so mirror-image lines get mirror-image (equal-when-symmetric) results. No x-odd tie-break here.
3. Hub girders are two-sided girders (spec.joist_spacing===nothing && !_spec_has_edge) and are SKIPPED by this function anyway; the C2 girder pairing comes from group_collinear_members! upstream, same maximum/cross-product logic.

CONCLUSION: collinear sharing MAINTAINS mirror symmetry; it is not the seed. With exactly-symmetric sections the whole loop (FEA -> demands -> MIP -> collinear) is reflection-covariant, so the two diagonals should never diverge. Since they DO, the seed must be an x-odd asymmetry that appears only under mirror-symmetric but NON-uniform section fields (the uniform-stiffness test cannot detect this, since a uniform field is also C2+mirror).

PROPOSED DECISIVE (cheaper) TEST before editing the MIP: take the converged chiral field, apply the x=12 mirror to it (swap the two diagonals' sections), re-solve FEA, extract demands. If demands come back as the exact mirror of the original -> FEA/demand path is reflection-exact and the chirality is a stable bistable pair (solver picked one handedness; fix = symmetric tie-break seeding). If demands are NOT the mirror -> the FEA assembly or demand-extraction is x-odd (the real bug to fix). scripts/runners/sdf_e0c0_seed_vs_tiebreak.jl is the starting point.
