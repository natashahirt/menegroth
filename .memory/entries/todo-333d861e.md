Found during Phase 1 audit by the adversarial critic (crit2, proven via scripts/runners/critic_near_singular_probe.jl driving real lateral_evaluator.jl). The reduced evaluator's singular detection is a THRESHOLD CLIFF: it throws SingularStiffnessError only at scale-normalized rcond<=1e-8, and the Phase 1 optimizer-boundary catch only penalizes when it throws. A layout near-singular in ONE direction (rcond in (1e-8,~1e-7], e.g. one near-dead Y-wall) does NOT throw; under a single-direction (X-only) design load — WITH accidental torsion, which the X-walls' lever arm resists — peak drift stays tiny (~1.7e-4) and the layout is reported FEASIBLE. The SAME layout under an equal orthogonal (Y) load gives drift ~3.3e3 (~167000x the 0.02 limit) = collapse mechanism. solve_wall_layout (layout_problem.jl:333) returns optimize_continuous(p) with NO final throwing re-validation of the selected minimizer; the FEM gate _assert_fem_nonsingular is exact-PD only and by its own docstring does not catch near-singularity. So a laterally-unstable-in-one-direction design can be returned as the optimum.

SEVERITY/CONTEXT: Largely PRE-EXISTING (not a Phase 1 regression — old pinv path behaved the same under single-direction load); LATENT today because the layout optimizer is NOT wired into any production design path (only a StructuralSynthesizer report test references it). Phase 1's four source fixes are verified solid (reviewer PASS, tester 225/225).

FIX (belongs here in Phase 10, depends on Phase 6): (1) require the layout objective/constraints to evaluate BOTH principal lateral directions (Phase 6 ASCE directional demand makes the single-direction trigger unreachable); (2) add a load-aware/direction-resolved lateral-stability check so an unexcited near-singular mode cannot pass; (3) make solve_wall_layout run a THROWING re-validation of the returned minimizer (not reusing only the 1e-8 cliff — needs a justified conditioning margin); (4) give the FEM gate a penalty-aware conditioning bound; (5) correct the lateral_evaluator.jl ~L56-60 docstring — the rcond metric is scale- but NOT origin-invariant (torsional term b3=cy*x-cx*y depends on the chosen origin, so the 1e-8 boundary wanders with origin). Acceptance threshold for Phase 10 survivor verification must reject near-singular/one-direction-only layouts. Cross-ref: Phase 1 todo-a8b3ef17, decision deci-893edf58.
