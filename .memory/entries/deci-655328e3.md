P1-3: post-level sync_asap! now passes loads_only=true only when _stiffness_token is unchanged across the level. The token covers frame-section K inputs (A, E, G, Ix, Iy, J, Ay, Az), element release type, end coordinates, current eccentricity, shell thickness/E/ν, and the joist-seat eccentricity map sync is about to write. Load magnitudes are not in the token. SS_SYNC_LOADS_ONLY=off forces the full refactorizing update. Wired in execute_graph! (cold design_building path) and run_target! barrier sync (incremental path). The kwarg on sync_asap! still defaults to false.

Verification: verify_design_graph.jl GRAPH_EXIT=0 (graph path matches the legacy stage loop, which always calls sync_asap! with loads_only=false). verify_design_graph_incremental.jl INCR_EXIT=0, 127/127. So the reuse is byte-identical to a cold refactorization on these buildings.

P1-4 (FEA _solve_load_case! values_only → loads_only) is NOT in this commit. A prior landing was not bit-identical and the design-graph gates cannot see it. scripts/runners/verify_fea_loads_only_oracle.jl is the separate exact-equality oracle and is not part of this pin.
