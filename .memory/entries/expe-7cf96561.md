Added an ε-constraint Pareto mode to the discrete optimizer (Pillar B completion). Weighted-sum ParetoScalarization only finds SUPPORTED (convex-hull) points; ε-constraint (minimize o1 s.t. o2 ≤ budget, sweep budget) recovers the COMPLETE front including non-convex/non-supported points.

Implementation (all clean optimize/solvers/discrete layer — zero collision with the other session):
- `optimize_discrete` (single + multi material) gained a `budget=(secondary_objective, value)` kwarg + optional `budget_cache`/`budget_caches`; multi overload also gained a `caches` kwarg so a sweep precomputes objective caches once. Budget constraint uses the secondary objective's own cache so the rebar/concrete split etc. match the primary. Infeasible budget (below the secondary optimum) returns an empty-assignment result (objective_value=Inf) rather than throwing. no-budget path is byte-identical (memo gated on budget===nothing); 152 existing optimize tests still green.
- New `pareto_front(checker, demands, geometries, catalog, material_or_materials; objective1, objective2, n_points, kwargs...)` + `ParetoPoint` struct. Anchors fix the secondary range; interior+endpoint budgets are solved; result is dominance-filtered and ordered. Forwards kwargs (optimizer, mip_gap, n_max_sections, …).

Key bug fixed during build: `_nondominated` computed `Inf - 1e-12*Inf = NaN` on the first point, so the filter returned an EMPTY front every time; fixed with an `isempty(out)` first-push guard.

Scale gotcha: the cache stores obj_coeffs in the *unconverted* unit objective_value naturally yields (A992 ρ is lb/ft³ ⇒ carbon NOT in canonical kgCO2e), so `budget_value` must be taken from a solve's own `objective_value`, never recomputed in canonical units. pareto_front is self-consistent because it derives budgets from the same caches.

Proof (scripts/runners/epsilon_pareto_demo.jl, HiGHS): 3 steel materials with identical capacity but (ρ,ecc) placing the middle material above the weight↔carbon hull line. ε-constraint recovers all 3 designs; a full weighted-sum sweep (w=0…1, step 0.02) recovers only 2 — it NEVER selects the non-supported material. A second 8-group case traces a 20-point mutually-non-dominated front spanning 5× weight/carbon.
