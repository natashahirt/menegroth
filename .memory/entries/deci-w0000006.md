# Decision - efficiency-upfront for the layout space

**Context.** The project owner accepted S1 but flagged that *optimizing over the shear-wall layout space efficiently will be tricky*, likes the sizer/synthesizer divide, and wants efficiency considered upfront. Layout search is combinatorially large (which walls, where, orientation, length, thickness, per story) and naively would re-run a full lateral FEM + full ACI sizing per candidate.

**Decision.** The sizer/synthesizer divide is also the **cost divide**, and the wall stack is designed for cheap layout evaluation from S1 onward:

1. **Analytic wall stiffness, mesh-free.** A wall's in-plane lateral stiffness (shear+flexure cantilever/pier) is computable in closed form from geometry + material. Carry these properties on `Wall` (built in S1) so the synthesizer's inner loop never needs a mesh.
2. **Swappable lateral evaluator behind one interface.** A **cheap tier** (S2 rigid-diaphragm closed form, O(walls) linear algebra) for the optimization inner loop; an **expensive tier** (S3 Asap FEM) to validate winners only. Same demand interface feeds the S1 checker either way.
3. **Layout as a cheaply-mutable object; incremental updates.** Represent a layout as a ground structure of admissible wall lines with present/absent + continuous size; adding/removing/moving one wall should be a rank-update of the story-stiffness/rigidity system, not a full reassembly. Reuse existing patterns: MIP warm-start, `snapshot!`/`restore!`, stage-gated sweeps that skip post-failure calcs.
4. **Separate the elastic layout objective from code sizing.** Optimize on a cheap elastic metric (drift / torsion / stiffness-to-weight, Zhang-Mueller style); run the full ACI checker (S1) and FEM (S3) only on the near-optimal set. Do not put per-clause code checks inside the optimizer's inner loop.

**Consequence for S1.** Even though S1 optimizes nothing, it must (a) give `Wall` analytic-stiffness fields and (b) keep the checker fully decoupled from the demand source, so S2's evaluator and S4's optimizer can layer on without reworking the type or the checker. This mirrors the existing decision to separate the design struct from the member/analysis struct (`deci-h000000f`).

## Update (2026-07-13) — finalized design, implemented S1/S2/S4

Implemented the paradigm as **gradient-based continuous topology optimization**, carbon-first and extensible, in a new `StructuralSizer/src/walls/` module. Validated by 33 known-answer assertions (`StructuralSizer/test/walls/test_walls.jl`); both `StructuralSizer` and `StructuralSynthesizer` precompile and load with the module wired in.

**Three implemented contracts (the extensibility guarantees):**

1. **Analytic, differentiable wall stiffness (`wall_section.jl`, S1).** In-plane lateral stiffness of a pier is a shear-flexure cantilever closed form, `k = 1/(H³/(β·E·I_eff) + H/(G·A_v))`, using ACI 318-19 Table 6.6.3.1.1(a) effective inertia (0.35 Ig cracked / 0.70 uncracked). Key result: because `I_eff ∝ t` and `A_v ∝ t`, **`k` is linear in thickness** — this is what makes the SIMP density relaxation clean. Analytic `∂k/∂t = k/t` provided. Bare-SI core + Unitful wrapper.
2. **Demand-decoupled ACI checker (`checker.jl`, S1).** ACI 318-19 §11.5.4.3 in-plane shear `Vn = (αc·λ·√f'c + ρt·fy)·Acv` with the §11.5.4.2 cap and §11.6.2 min reinforcement; capacity functions take only section+material, demand supplied separately → same checker serves every demand tier. Returns `CheckResult` (carries the clause for the report-feedback contract). Hand-calc validated (αc plateau/transition, φ=0.75).
3. **Swappable `AbstractLateralEvaluator` (`lateral_evaluator.jl` S2 + `fem_evaluator.jl` S3).** `evaluate_lateral(ev, walls, loads) -> LateralResult(story_disp, drift, wall_forces, torsion)`. The cheap **`ReducedDiaphragmEvaluator`** is the crux: 3 DOF/story rigid diaphragm, each story `K = Σ kᵢ bᵢ bᵢᵀ` (**rank-1 per wall** → Woodbury-friendly, O(walls) assembly, O(1) solve). Fully differentiable; **analytic drift sensitivity** `∂drift/∂kᵢ` via the 3×3 adjoint (validated against finite differences to 1e-4). Skew walls handled by the geometry vector `b = [cx, cy, cy·x − cx·y]`; torsion + ASCE 7 accidental eccentricity fall out automatically.

**S4 (`layout_problem.jl`).** `WallLayoutNLPProblem <: AbstractNLPProblem` over a ground structure of `WallCandidate` lines. Design vars = per-candidate SIMP density ρ∈[ρ_min,1]; thickness `t = ρ·t_max`, penalized stiffness `k = ρ^p·k_max` (intermediate densities stiffness-inefficient → drives to present/absent). `objective_fn = MinCarbon` (linear in ρ); `constraint_fns` = per-story drift/torsion + per-wall shear proxy, all from `ReducedDiaphragmEvaluator` (cheap tier only in the inner loop). Solves via the **existing** `optimize_continuous(:ipopt)` — no new solver.

**Objective extensibility (proven, `objective-extensibility`).** Swapping carbon→drift or a scalarized multi-objective requires only a new `AbstractObjective`: added `MinDrift` and `WeightedLayoutObjective`; the evaluator already returns carbon + drift jointly, so problem/solver are untouched.

**S3 FEM tier (`todo-w0000004`) — now implemented & validated.** `FEMLateralEvaluator` assembles a real mixed Asap shell model: vertical walls meshed as `ShellTri3` on shared nodes (continuous across stories), per-floor stiff fan-triangulated diaphragms with centroid master nodes, base fixity, `NodeForce` story loads, `solve!`. Drift from master-node displacements; base-story wall shear recovered exactly from nodal reactions (upper stories via `Nxy`, first-cut). Cross-checked against the reduced oracle on a symmetric core: walls equilibrate the applied shear, torsion 1.0, drift same order (FEM stiffer for squat piers). An Asap capability audit confirmed nothing was missing at the library level — only menegroth-side assembly, which is now done. Remaining: multi-story upper-panel shear calibration, `to_asap!` diaphragm wiring for the gravity model, optional P-delta.

**Canon caveat.** All ACI clause/page citations are recorded from ACI 318-19 from memory and tagged `VERIFY`; they must be reconciled against the extracted zettelkasten canon (StructurePoint spWall worked examples, `corpus: sp-de-shear-wall-aci19`, are the intended full-capacity validation oracle) before production use — per the `implement-design-system` skill stage-1 HARD STOP.
