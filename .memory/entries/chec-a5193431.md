Wired the strength↔drift coupling into `resize_for_drift!`:

- **`floor_I_fn(model, u)` callback**: strength floor recomputed each outer iteration from the just-solved EXACT forces (the governor already re-solves, so ~O(n) extra). `floor_I` stays as a hard absolute lower bound. Convergence now requires BOTH drift and strength met. Each member sized to max(drift_target, strength_floor), recomputed fresh each iteration (no monotone ratchet).

- **Accelerator (optional, `accelerate=true`)**: `predict_floor(target)` predicts the next-solve strength floor WITHOUT a fresh factorization — u_pred = u + linear_response(model, -ΔK u; links) (one back-sub, ΔK from Asap.global_K at the trial section), then evaluates floor_I_fn at u_pred AND the target element stiffnesses (el.K temporarily set to target, then restored; model.S/factor untouched).

**Two bugs found + fixed during testing** (accelerate diverged to a 7×–70× oversized base vs non-accel):
1. predicted floor evaluated member demands with OLD el.K, not the target → now sets el.K to target for the floor eval.
2. **Root cause**: first-order Δu ≈ -K⁻¹(ΔK u) overshoots (even sign-flips) for LARGE stiffness jumps → garbage u_pred → huge predicted floor; and since the resizer never shrinks a slack member and convergence accepts any safe design, the overshoot locks in. **Fix: step trust region** (`accel_trust=0.3`) — the predictor is used only when the proposed relative stiffness change is small (near convergence, where first-order is accurate); big early jumps use the exact floor_now. Removed the monotone max-flooring (it compounded the lock-in).

Guarantee: the accelerator changes convergence SPEED, not the converged design. Test asserts accelerate & non-accelerate reach the SAME sizes (rtol 1e-6) with accelerate iters ≤ non-accel, plus strength+drift both met. Sizer governor 28/28, lints clean.
