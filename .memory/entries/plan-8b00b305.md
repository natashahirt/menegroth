Goal: consolidate the fragmented footing design surface. Today there are five design_footing methods (spread, column strip, wall strip, mat, IS spread) and the combination loads arrive as four differently-named keyword pairs over two element types: column actions (service_actions/strength_actions, column_service/column_strength) as Vector{FootingAction}, and wall lines (service_cases/strength_cases, wall_service/wall_strength) as Vector{Vector{WallLineDemand}}. The centroid-on-gravity-resultant + kern + grow + per-combination envelope logic is written three times (strip_footing.jl, mat_footing.jl, wall_strip_footing.jl) with their own sign bookkeeping.

Design decisions (locked):
1. One container `FootingLoads` holding demands, positions (2-D xy), column_service/column_strength (Vector{Vector{FootingAction}}), walls, wall_service/wall_strength (Vector{Vector{WallLineDemand}}). One inner constructor runs every alignment invariant: _strip_validate_actions, wall/column length+label match, and the 'do not mix a column lacking actions against a seismic wall line' rule.
2. Unified entry design_footing(::AbstractFoundation, loads::FootingLoads, soil; opts). Existing positional methods become thin wrappers that build FootingLoads and call it, so all tests and call sites stay green during migration.
3. Keep point-load and line-load statics distinct inside the container; the win is unified construction and one entry, not forced polymorphism. Positions move to 2-D xy; strip projects onto its axis.

Sequencing, each landing with the StructuralSizer + StructuralSynthesizer foundation suites green:
- Phase A: FootingLoads type + unified entry + Synthesizer builder replacing _aligned_column_actions and _wall_combination_cases and the manual gravity-demand assembly. Pure API consolidation, no behavior change.
- Phase B: extract the shared plan engine (centroid on gravity service resultant, _eccentric_soil_pressure kern, grow length-or-width, envelope each combination). strip/mat/wall call it. This is the correctness dedup; highest risk; behind green tests.
- Phase C: uniform analysis-method selection (RigidMat/WinklerFEA/ShuklaAFM exposed the same way for strips and walls, not just mats).
- Phase D: the deferred correctness work rides on B, written once: flexible section (Winkler/Shukla/wall-on-elastic) enveloped per combination with the ACI 336.2R 6.1.2 Step 3 20% gate applied per strength combination; pattern live load as footing combinations; net-tension and sliding checks (both need a user number first).

Safety: this is a load-bearing refactor of safety-critical statics. Land Phase A and B as pure restructurings with the existing foundation tests green before any new check rides on the unified engine. Do not change spread/strip/mat/wall numerical behavior in A-C. Current state before this plan: committed 2af5e9c8 (combinations stay on the gravity resultant for the rigid shallow family).
