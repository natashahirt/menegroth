## Context
First clean end-to-end run of the consolidated exact-first gates (`run_all_gates.jl`, supervised, depot quiet, Gurobi licensed) surfaced a failure that never ran to completion overnight (depot SIGKILLs): 3/4 gates green, but `verify_design_graph_incremental.jl` exited 1.

## Root cause (diagnosed, not guessed)
`optimize_binary_search` threw `ArgumentError: No feasible sections for group [1]` at the `[12]` override **precedence** sub-test (gate line ~836). The test hard-codes a single-section override catalog `[W21X44]` on `build_override_beam_struc()` — a 20 ft fixed-pinned beam under 2.8 kip/ft whose GOVERNING moment is the HOGGING moment at the fixed end (140 kip·ft).

`explain_feasibility` showed every check passes for W21X44 EXCEPT `flexure_neg` (hogging Chapter-F LTB, AISC 360-16 §F2): demand 140 kip·ft vs capacity 103 kip·ft, ratio 1.357. The hogging check (`_hogging_ltb_inputs`, checker.jl) treats the bottom flange as unbraced over the full span `Lb_neg = L = 20 ft` at `Cb=1.0` — documented engineering judgment. W21X44 is a deep, LTB-weak shape, so it is CORRECTLY rejected. W24X68 (0.39) and W24X103 (0.20) pass; `all_W()` correctly picks chunky LTB-strong W14X43 as lightest feasible. The sizer is working; it is conservatively correct.

## Why it regressed
Precedence test authored July (`be762cd6`, Run 4, all gates green). The hogging Chapter-F LTB check was added/tightened AFTER that ('signed beam moments … Cb=1.0, Lb=L hogging'), making the hard-coded W21X44 genuinely infeasible for this fixture. NOT caused by overnight Phase 0 (header-only refactor, 14 ins/101 del) or Phase 2 (API-only) — confirmed via git show/blame; failing path (binary_search.jl, members/utils.jl) untouched.

## Fix (user-ratified: fix the stale test, leave checker)
Precedence sub-test now uses two CONFIRMED-FEASIBLE distinct sections isolating PRECEDENCE not catalog adequacy: `catalog_override=[W24X103]` (lower precedence) vs per-design `override=[W24X68]` (wins) → assert section == W24X68. Added comment pinning WHY (hogging LTB rejects deep LTB-weak shapes) so it cannot silently re-break.

## Verified
`verify_design_graph_incremental.jl` standalone re-run → ALL CHECKS PASS (127/127), precedence green. Other 3 gates green in full run and unaffected (test-only change). Full suite now effectively 4/4.
