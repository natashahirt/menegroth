Locked 2026-11-02 in a plan review.

1. Build order: span line and supports first, then shared checks, then coefficients on that line, then the strip (checked against the coefficients), then the shell with beam line supports (checked against the strip).

2. The flat-plate shell holds the slab up at columns only. Panel edges are free vertically. One panel on four corner columns sags along its edges, where the real slab hogs over the beam, so the top bars over the beams would be missed. Unconservative. A panel with fewer than two columns throws. The shell is not a valid fallback for a beam-supported panel until beam supports and continuity into neighboring panels are added.

3. Until a method actually runs, OneWay and TwoWay slabs store design_details = (analysis_status = :not_analyzed, analysis_planned, analysis_reasons). They no longer store method_used, which the building result was copying. SlabDesignResult.analysis_status carries the status. Building panel test: 13/13.

4. Open: SlabDesignResult defaults converged, deflection_ok, and punching_ok to true, so an unanalyzed panel still reads as passing.

5. Two-way slabs on beams are under discussion with the user, not decided.
