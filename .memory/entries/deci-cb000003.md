# Why: one optimizer serves every design code

`AbstractCapacityChecker` (`optimize/core/interface.jl`) lets a single MIP solver (`optimize_discrete`) size AISC, ACI, PixelFrame, and NDS members without code-specific JuMP models. Checkers implement `create_cache -> precompute_capacities! -> is_feasible` (fast, short-circuiting, used in the MIP hot loop) and a separate `explain_feasibility` (slow, runs all checks, returns per-check `ratio` + `code_clause`) that is deliberately kept OUT of the hot loop and called post-solve for diagnostics.

This is why `optimize/` loads before `members/`: solvers depend only on the abstract interface; concrete checkers/caches (`AISCChecker`/`AISCCapacityCache`, `ACIColumnChecker`, `ACIBeamChecker`, `PixelFrameChecker`) plug in later. Each `CheckResult` carries a `code_clause::String` (e.g. "AISC 360-16 G2", "ACI 318-19 22.6") — a natural hook for synapse links to zettelkasten clause notes.
