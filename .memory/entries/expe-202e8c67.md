**Workstream R first proving slice (§9) — complete, zero edits to live owners.**

Key de-risk discovered: `optimize_discrete` ALREADY exposes the two hooks R.3 needs, both byte-identical when `nothing`:
- `mip_start` — per-group prior catalog index seeded onto branch-and-bound (pure HINT, cannot change the optimum).
- `feasible` — per-group ALLOWED catalog indices, INTERSECTED with capacity screening (can only remove candidates; checker still certifies every pick).

So R.3 is glue, not new MIP machinery. Added `relaxation_warm_start(I_catalog, A_catalog, I_targets; Z, k)` to `section_relaxation.jl` — pure index math that fits the scaling law, projects each continuous target, builds the ±k band, and (critical) maps the law's I-SORTED indices back to CATALOG-ORDER via the sort permutation so they drop straight into `mip_start`/`feasible`. Returns `RelaxationWarmStart(mip_start, band, gap, grown)`. Tests use a deliberately UNSORTED catalog to prove the permutation bookkeeping; 48/48 green.

**Benchmark** (`scripts/runners/relaxation_warmstart_benchmark.jl`): deflection-governed steel-beam sizing on the full W catalog (283 sections, 30 groups), driving the REAL `optimize_discrete`. Deflection-governed on purpose — there I is the single governing property, and the required I is encoded exactly through the AISC deflection check (Ix ≥ δ_max_LL·I_ref/(limit·L)), so the owner's lightest-feasible pick == project_to_catalog(I_req) by construction (non-circular: target is Euler–Bernoulli serviceability, not the catalog/solver).

Results (fair fresh-solve timing — warmup on a different-sized sub-problem so the MIP memo can't pre-cache any timed key):
- Cold full-catalog solve: 11,965 ms.
- Warm start (mip_start): 6,450 ms — ×1.86, sections BYTE-IDENTICAL to cold.
- Band (feasible, k=2): 5,512 ms — ×2.17, objective gap 0.0000%, sections identical.
- §9 acceptance (projection vs cold MIP pick, I-rank steps): max 0, mean 0, 30/30 within ±1 — EXACT.

Timing gotcha recorded: `optimize_discrete` memoizes on its arg tuple (incl. mip_start/feasible), so a naive warmup+cold caches the cold key and makes cold look instant (34 ms) while warm looks 100× slower. Fixed by warming up on a 3-group sub-problem.
