# Decision — wall in-plane axial–flexure (P–M) method & guards

**Context.** The spWall worked example computes wall in-plane moment capacity two
ways that DISAGREE by ~10 %: the Cardenas closed form (hand calc, φMn≈4808 kip-ft)
and the spColumn full strain-compatibility interaction (φMn≈5319 kip-ft). We had
to choose what the pass/fail check reports.

**Why (the decision).**
1. **Implement BOTH methods.** Cardenas closed form (matches the hand calc, cheap,
   nearly differentiable — good for the S4 optimizer later) AND a strain-
   compatibility interaction diagram (ACI §22.2, valid in every axial regime,
   generalized from the RC-column engine by smearing the distributed steel into
   layers).
2. **The CheckResult reports the CONSERVATIVE `min(Cardenas, strain-compat)`.**
   Rationale: Cardenas assumes the whole tension block yields, which is only true
   in the tension/transition regime; the strain-compat curve is valid everywhere.
   Taking the min can never pass a wall the rigorous method fails, and reproduces
   the (conservative) hand value in the worked example. Chosen over "use spColumn
   value" (less conservative) and over "Cardenas only" (invalid at high axial).
3. **Axial is bounded by ACI 318-19 §22.4.2.1** (`Nu ≤ φ·0.80·P0`) BEFORE the
   moment term — a P–M check must not pass an over-compressed wall on moment alone.
4. **`fy`/`Es` must be Unitful** — a bare-number ksi/Pa mismatch would 7×10⁶
   overstate steel strength; there is one accepted, unit-carrying spelling.

**How (verification).** Independent reviewer + adversarial critic (separate model
families) red-teamed the first cut and found exactly these gaps (2 BLOCKER: unit
footgun, no tension-controlled guard; 2 MAJOR: no axial cap, bogus solver return
above squash). All fixed; re-verified. spWall reproduced to <0.2 %; 91/91 wall
tests; report §3F all green.

**Scope boundary (ENGINEERING JUDGMENT, documented, not silent).** Special
boundary elements §18.10.6 (canon absent → todo-w0000010), out-of-plane/slender
§11.8 (todo-w0000008), and bar development/splices are explicitly OUT of this
module — a passing P–M check is necessary, not sufficient.
