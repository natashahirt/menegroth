Static-first end-to-end audit of the iterative design path (Design Harness/API -> StructuralSynthesizer -> StructuralSizer -> Asap). No production code or formulas changed. Full report: `documents/20261014_iterative_analysis_architecture_performance_audit.md`; companion canvas at `~/.cursor/projects/.../canvases/iterative-analysis-audit.canvas.tsx`.

## Architecture (verified in source)
Three orchestration layers + a read-only projection:
- **A Cold full design** `design_building` -> `build_design_graph` -> `execute_graph!` (`executor.jl`): the production default for POST /design (`routes.jl` L648) and chat `run_design` (`chat.jl` L4543).
- **B Incremental DAG** `run_target!`/`DesignSession` (`scheduler.jl`): content-fingerprint invalidation, per-node memo, warm-state factorization reuse. Verified bit-identical (12/12, `verify_warm_state_incremental.jl`) but **not wired to the API**.
- **C Micro-experiments** (`micro_experiments.jl`): cached what-if, no struc mutation.
- **D DesignState** (`design_state.jl`): read-only projection.

Geometry cache (`cache.jl`) excludes params, so a param-only change is a cache 'hit' that still pays full `prepare!` + whole pipeline + per-level `sync_asap!`.

## Ranked findings
- **P0-1 (Evidence, H/H):** API/chat run cold `design_building` on every param change; incremental engine idle. Hold a `DesignSession` per geometry_hash; route param-only changes through `redesign_incremental!`.
- **P0-2 (Evidence, H/H):** per-node memo is whole-`BuildingStructure` `deepcopy` (`NodeMemo.state`, `capture_node_state`/`restore_node_state` in `core/snapshot.jl`); all-clean level restore is another deepcopy. Replace with the composable per-slab/column snapshots already unit-tested (`restore_slab_node_writes!`/`_adopt_larger_column!`).
- **P1-3 (Evidence, H):** cold `execute_graph!` calls `sync_asap!` with default `loads_only=false` -> full refactorization every sync; `loads_only=true` path exists, documented bit-identical, used only by incremental engine. Pass it when write-set provenance proves K unchanged.
- **P1-4 (Hypothesis):** FEA `_solve_load_case!` uses `update!(values_only=true)` which nulls the CHOLMOD factor; reuse factor like `_solve_per_cell_live!`.
- **P1-5 (Hypothesis):** FEA flat-plate D/L x `:fea_resolve` pattern x combo envelope is multiplicative.
- **P2-6 (Hypothesis):** per-iteration column MIP rebuilds JuMP model + O(groups x catalog) screening; thread `mip_start`, memoize feasible sets.
- **P2-7 (Hypothesis, ENG JUDGMENT):** `member_group_demands` resolution=200 x patterns per sizing call.
- **P2-8 (Evidence):** `_col_cache=nothing` rebuilt per slab on cold path (`_make_slab_node_fn` L503); warm path reuses. Default warm for sweeps.

## Consolidation
C1 single orchestrator facade; C2 unify the two snapshot models (`DesignSnapshot` vs whole-struc); C3 single pipeline SSoT (`build_pipeline` vs `build_design_graph` + stage-count guard); C4 break cycles / narrow fan-out (FEA cluster, api chat/narrate/routes, Asap 35-import root); C5 runner/harness consolidation (~196 runners, verify twins duplicate invariants); C6 gitignore grasshopper build artifacts + track untracked test files (code-graph grade F is driven by C# god-objects + build artifacts, not the Julia core).

## Measurement (deferred)
Exact-first gates exist (`verify_design_graph*.jl`, `verify_warm_state_incremental.jl`) but there are **no CI perf gates and no run-ledger wiring**, and no `BenchmarkTools`/`Profile`/`TimerOutputs` in sources. Proposed: additive instrumentation (`recomputed/restored_nodes`, `memo_bytes`, `sync/factorization_count`, peak RSS, setup/solve split); benchmark matrix (FEA vs DDM/EFM, steel beam+col, 5x reruns cold vs warm, large catalog MIP); run-ledger with env fingerprint (root + Asap SHA, Julia version, SS_ENABLE_*, solver backend); tiered gates (A exact-first mandatory, B package tests, C perf soft gate). All solve-path changes gated on exact-first before any speed claim; demand/capacity changes are engineering judgment.
